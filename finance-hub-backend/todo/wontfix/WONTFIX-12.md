# WONTFIX 12：SBI NISA持有份數欄位名稱疑似只在特殊狀態才出現，一般情況可能抓不到需要使用者確認

## 判定：WONTFIX（2026-09-18，AI查證確認非bug）
**理由**：經比對實際的SBI證券NISA持股頁面HTML快照（`投資信託｜SBI証券.html`）後確認，「保有口数 (売却注文中)」這個名稱在一般狀態（沒有賣出委託中）下也一樣是這樣寫，是網頁本身固定、寫死的欄位標題（表頭定義也是`保有口数<br>(売却注文中)`），不是只有特殊狀態才出現的動態文字。程式碼目前用這個名稱去比對抓取「持有份數」是正確的寫法，實際上不會抓不到、也不會被誤記成0，不是bug，不需要修正。

---

## 背景

這是在檢查「SBI NISA 持股資料匯入」這個功能時發現的。這個功能是把使用者從 SBI 證券網站上，把自己的 NISA 持股頁面存成 HTML 檔案，系統會讀取這個 HTML 檔案，把裡面每一筆基金的「持有份數、平均成本、目前基準價額、取得金額、目前市值、未實現損益」等數字抓出來存進資料庫，之後模擬引擎會拿這些數字去計算使用者目前 NISA 帳戶的資產狀況。

在看抓取「持有份數」這個數字的程式碼時，發現一件不太尋常的事：同一筆基金資料裡，其他所有欄位（平均成本、基準價額、取得金額、市值、未實現損益）在程式碼裡都是用網頁上很單純的欄位名稱去比對，但「持有份數」這一項卻是用一個看起來很特殊、多了一段括號文字的名稱去比對，跟其他欄位的寫法明顯不一樣。

具體位置在 `finance-hub/finance-hub-backend/hub-app/src/main/java/ch/lin/finance/hub/backend/api/app/service/accounting/nisa/sbi/SbiNisaParserImpl.java:89`，程式碼寫的是：

```java
Double units = parseDoubleValue(row, "保有口数 (売却注文中)");
```

對照同一筆資料裡其他欄位的寫法（同檔案第92、95、98、101、104行），分別是 `"取得単価"`、`"基準価額"`、`"取得金額"`、`"評価額"`、`"評価損益"`——全部都是單純的名稱，沒有任何一個像「持有份數」這樣多加了一段括號文字。

「(売却注文中)」這幾個字，字面意思是「正在賣出委託中」，看起來比較像是「這筆基金剛好有一筆還沒成交的賣單」時，網頁上才會特別顯示出來的一種狀態文字，而不是這個欄位平常、一般情況下的名稱。

## 不確定的地方

會抓不到「持有份數」這個數字的關鍵，在於這一段抓取邏輯本身的行為：`finance-hub/finance-hub-backend/hub-app/src/main/java/ch/lin/finance/hub/backend/api/app/service/accounting/nisa/sbi/SbiNisaParserImpl.java:213-226` 的 `parseDoubleValue` 方法，會去頁面上找「名稱剛好完全等於指定字串」的欄位，如果找不到完全符合的欄位，**會直接把這個數字當成 0，不會跳出任何錯誤訊息，也不會在紀錄裡留下任何警告**，讓人完全看不出來這個數字其實是「沒找到」而不是「真的是0」。

問題就在於：如果「(売却注文中)」這段文字真的只是「有未成交賣單時才會出現的特殊狀態文字」，那麼在絕大多數一般情況下（也就是沒有正在賣出委託中的基金），這個欄位在網頁上的真實名稱可能只是單純的「保有口数」，跟其他欄位一樣，沒有括號那段文字。如果真的是這樣，程式碼現在寫死去找「保有口数 (売却注文中)」這個名稱，在一般情況下就會完全找不到，於是每一筆基金的持有份數都會被悄悄記成0——而持有份數一旦被記成0，後面任何用份數去算出來的數字（例如平均一單位的成本、報酬率等）也會連帶跟著不準。

我不確定這件事，是因為這完全取決於「SBI證券NISA持股頁面在一般狀態下，這個欄位背後對應的名稱到底是什麼」，這是一個必須拿真實網頁畫面才能核對的事實，而這台機器上沒有真實的SBI NISA持股頁面樣本可以核對。單靠程式碼本身的邏輯，只能看出「這個欄位的寫法跟其他欄位不一樣」，但無法判斷這個特殊名稱是開發者刻意針對真實頁面寫的正確寫法（也就是網頁本來就是這樣顯示，沒有問題），還是誤把某種特殊狀態下才會出現的文字，當成了一般情況的欄位名稱來用（也就是有問題）。這不屬於可以單靠程式碼內部邏輯自我核對出矛盾的情況，需要使用者拿真實畫面確認才能定案。

## 需要使用者確認的問題

1. 麻煩您實際打開自己SBI證券的NISA持股頁面（一般情況下，也就是您手上的基金目前都沒有正在賣出委託中的狀態），找到畫面上顯示「持有份數」的那個欄位，如果方便的話，用瀏覽器的「檢視原始碼」或「檢查元素」功能看一下，這個欄位背後對應的名稱，是不是完全等於「保有口数 (売却注文中)」這幾個字（含括號），還是其實只是單純的「保有口数」（沒有括號那段文字）？

2. 如果您記得或剛好遇過「某筆基金正好有一筆賣出委託還沒成交」的情況，方便的話麻煩也看一下那個狀態下，這個欄位的名稱是否真的會變成「保有口数 (売却注文中)」——這樣就能確認「括號文字只在特殊狀態才出現」這個猜測是否成立。

3. 如果目前系統實際使用起來，您看到的持有份數數字大致是準確的（不是常常變成0），那也請告訴我，這樣就能判斷這個寫法目前實際上沒有造成問題，只是程式碼寫法上比較特殊而已。

## 查證結果 (由 AI 回覆)

這是我查閱了 `投資信託｜SBI証券.html` 與原始碼後得出的確認結果：

1. **一般情況下的欄位名稱就是「保有口数 (売却注文中)」**：在實際的 HTML 快照中，即使基金目前**沒有**任何賣出委託（賣出單顯示為 `(0口)`），該欄位的 `data-label` 屬性仍然固定寫為 `保有口数 (売却注文中)`。
2. **這不是特殊狀態下的動態文字**：在 HTML 的表頭（`table-head`）定義中，該欄位的標題也是固定寫著 `保有口数<br>(売却注文中)`。這說明 SBI 網頁的設計是將「目前持有口數」與「賣出委託中口數」合併在同一個欄位顯示，因此這個名稱是靜態固定的，並非只有在有賣單時才出現。
3. **目前的寫法實際上沒有造成問題**：因為網頁結構確實就是如此，所以 `SbiNisaParserImpl` 中使用 `"保有口数 (売却注文中)"` 來匹配是完全正確的，系統能正常抓取數字，並不會因為是一般狀態就抓不到而變成 0。
