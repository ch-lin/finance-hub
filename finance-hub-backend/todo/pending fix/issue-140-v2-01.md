# Issue 140 v2 — Phase 1：基礎設施與模擬引擎隔離（症狀 2）

> 總覽與設計背景見 [issue-140-v2.md](file:///Users/edward/Desktop/Projects/youtube-data-hub-wrapper/finance-hub/finance-hub-backend/todo/pending%20fix/issue-140-v2.md)。本階段可獨立實作與驗證，不會破壞既有列表 API，也不依賴 Phase 2/3。

## 目標
1. 建立全專案共用的權限守衛 `OwnershipGuard` 與請求視角解析器 `ScopeResolver`（含 `Specification` 條件產生器），供後續階段直接呼叫。
2. 徹底解決「症狀 2」：讓模擬引擎與個人設定在 SQL 層強制只抓本人資料，完全與 `X-View-Scope: FAMILY` 脫鉤。

---

## 一、建立共用基礎設施

### 1. `ScopeResolver`（解析 `X-View-Scope` 與查詢 Scope）
- **職責**：取代 `OwnerFilterInterceptor` 把 Scope 塞進 Hibernate Session 的做法，改為直接從當前 HTTP Request 解析 `X-View-Scope` Header，提供給列表查詢的 `Specification` 使用。
- **規則**：
  - 取得 `currentUserId = SecurityUtil.getCurrentUserId()`（`SecurityUtil.java:47`）。
  - 若在非 HTTP 執行緒（如背景 Job）或未帶 `X-View-Scope: FAMILY`，一律回傳個人 Scope（`personal`）。
  - 若帶 `X-View-Scope: FAMILY`，呼叫 `familyService.getFamilyMemberIds(currentUserId)`（`FamilyService.java:79`）；若該使用者不屬於任何家族（`FamilyService` 拋出 `IllegalStateException`，見 `OwnerFilterInterceptor.java:77-80`），回傳 `ResponseStatusException(HttpStatus.FORBIDDEN)`。

### 2. `OwnershipGuard`（單筆權限檢查 ＋ 列表 `Specification`）
注入 `FamilyService` 與 `ScopeResolver`，統一集中管理所有存取規則：

- **單筆寫入／刪除（最嚴格：只限本人）**：
  - `requireOwner(MultiUserBaseEntity entity)` / `requireOwner(String ownerUserId)`
  - 比對 `Objects.equals(ownerUserId, SecurityUtil.getCurrentUserId())`；不符時丟出 `EntityNotFoundException`（回傳 404，避免暴露他人 ID 是否存在；若特定業務需保留家屬唯讀提示，可依需求明確處理 `ReadOnlyFamilyRecordException`）。
  - `loadOwned(JpaRepository<T, Long> repo, Long id)`：先 `findById(id)`，再呼叫 `requireOwner(entity)` 後回傳，用於取代各 Service 零散的 `findById` ＋ 更新／刪除流程。
- **單筆唯讀（本人，或同家族且非 `PRIVATE`）**：
  - `requireReadable(MultiUserBaseEntity entity)` / `requireReadable(String ownerUserId, PrivacyLevel privacyLevel)`
  - 1. 若為本人，直接放行。
  - 2. 若 `privacyLevel == PrivacyLevel.PRIVATE`（`PrivacyLevel.java:16`），丟出 `EntityNotFoundException`。
  - 3. 呼叫 `familyService.getFamilyMemberIds(currentUserId)`（接住 `IllegalStateException` 視為 `false`），確認 `ownerUserId` 在家族成員名單內才放行。
- **一般列表查詢用 `Specification`（供 Phase 3 使用）**：
  - `readableSpec()`（或泛型 `<T extends MultiUserBaseEntity> Specification<T> readableSpec()`）：
    - 個人 Scope：產生 `ownerUserId = :currentUserId`。
    - 家族 Scope：產生 `ownerUserId IN (:familyUserIds) AND (ownerUserId = :currentUserId OR privacyLevel != PrivacyLevel.PRIVATE)`。

> **測試注意事項**：`SecurityUtil.getCurrentUserId()`（`SecurityUtil.java:49`）要求 `SecurityContextHolder` 內必須為 `JwtAuthenticationToken`。單元或整合測試若未走真實 JWT Filter，需在測試上下文注入模擬的 `JwtAuthenticationToken`。

## 二、模擬引擎與個人設定改採顯式 `ownerUserId` 查詢（症狀 2）

所有模擬引擎與個人設定查詢必須**永遠鎖定本人**，不可使用 `ScopeResolver` 的 `FAMILY` 視角，也不得依賴 Hibernate Filter。
