# Issue 140 v2 — Phase 2：單筆依 ID 讀寫與 `ExpenseServiceImpl` 防護（症狀 1 ＋ 症狀 3）

> 前置條件：完成 [issue-140-v2-01.md](file:///Users/edward/Desktop/Projects/youtube-data-hub-wrapper/finance-hub/finance-hub-backend/todo/pending%20fix/issue-140-v2-01.md) 中的 `OwnershipGuard`。總覽見 [issue-140-v2.md](file:///Users/edward/Desktop/Projects/youtube-data-hub-wrapper/finance-hub/finance-hub-backend/todo/pending%20fix/issue-140-v2.md)。

## 目標
將系統內所有「依 ID 讀取、修改、刪除單筆資源」的入口，統一改為透過 `OwnershipGuard` 把關，同時修補症狀 1（`findById`/`deleteById`）與症狀 3（`entityManager.find()`）。

---

## 一、統一改寫原則

1. **寫入／修改（`PUT` / `PATCH`）**：
   - 將 `repository.findById(id)` 改為 `ownershipGuard.loadOwned(repository, id)`。
   - 若 Service 原本存在部分欄位的擁有者檢查（如 `MortgageRecordServiceImpl.java:58-62` 只在稅務抵扣分支檢查），改用 `loadOwned` 後即可在方法入口統一攔截所有欄位。
   - **注意 `save()` 帶 ID 走 `merge()` 的情境**：凡是 `createOrUpdate...` 允許傳入 `id` 更新既有資料的入口（例如 `issue-140.md:L239` 提到的 `PensionRecordServiceImpl`），必須先經 `ownershipGuard.loadOwned(repository, id)` 載入並更新欄位，禁止直接對外部傳入的 ID 呼叫 `save()`。
2. **刪除（`DELETE`）**：
   - 禁止直接呼叫 `repository.deleteById(id)`。
   - 一律改為先 `T entity = ownershipGuard.loadOwned(repository, id);` 再呼叫 `repository.delete(entity);`。
   - 若該資源不存在或屬於他人／家人，一律在 `loadOwned` 階段直接丟出 `EntityNotFoundException`（404），消除 `deleteById` 靜默略過的問題。
3. **唯讀（`GET /{id}`）**：
   - 先透過 `findById(id)` 取得實體（找不到丟 `EntityNotFoundException`），再呼叫 `ownershipGuard.requireReadable(entity)`。
   - 本人可讀；同家族且 `privacyLevel != PRIVATE` 可讀；其餘一律拋出 `EntityNotFoundException`（404）。

### 1. 症狀 1：單筆 CRUD Service（完整明細見 `issue-140.md:L25-L37`）
- **房貸**：`MortgageRecordServiceImpl`（`updateMortgage`、`deleteMortgage`，已核對 `MortgageRecordServiceImpl.java:165-210`）

- **小孩資料**：`ChildProfileServiceImpl`（`getInternalChildProfile` 被查詢／更新／刪除／教育費推算共用，需依「唯讀」與「異動」區分呼叫 `requireReadable` 或 `requireOwner`）

- **人生事件**：`LifeEventServiceImpl`（刪除）

### 2. 症狀 3：`ExpenseServiceImpl.getExpenseDetail`（已核對 `ExpenseServiceImpl.java:93-126`）
- `AmazonItem`、`RakutenItem`、`SofmapItem` 繼承 `PrivacyOverrideBaseEntity`，本身沒有 `ownerUserId` 欄位，擁有者與隱私層級掛在 `item.getOrder()` 上（見 `issue-140.md:L316-L319`）。
- 在 `ExpenseServiceImpl.java:108-123` 透過 `entityManager.find(...)` 取得 `item` 後，若 `item != null && item.getOrder() != null`：
  - 呼叫 `ownershipGuard.requireReadable(item.getOrder().getOwnerUserId(), item.getOrder().getPrivacyLevel())`。
  - 若 `item == null` 或權限檢查失敗，維持 Controller 期待的回傳 `null`（404）或統一丟出 `EntityNotFoundException`。

## 三、Phase 2 驗收標準
- 上述 11 個 Service 與 `ExpenseServiceImpl.getExpenseDetail` 皆不再有無保護的 `findById`、`deleteById`、`entityManager.find()`。
- 針對所有 `PUT`/`PATCH`/`DELETE /{id}` 與 `GET /{id}` 補齊跨戶隔離測試：
  - 無家族關係的 User A 用 User B 的數字 ID 呼叫，全部回傳 404（含 `GET /expenses/AMAZON_{id}/details`）。
  - 同家族的 User A 對 User B 標記為 `SHARED` 的資源呼叫 `GET` 成功，呼叫 `PUT`/`PATCH`/`DELETE` 被拒絕（404）。
  - 同家族的 User A 對 User B 標記為 `PRIVATE` 的資源呼叫 `GET` 被拒絕（404）。
