## 修改2：新增一個共用方法，算出「這一年退休月是幾月」

這個計算會被191-03（方向二：判斷在職段/退休段怎麼分流）跟191-04（方向三：房貸控除分類）兩份文件都用到，只能實作一次，不能各自算一份（否則兩處對「退休月是幾月」的理解可能不一致）。

**放在哪裡**：建議放在[SimulationContext.java](file://finance-hub/finance-hub-backend/hub-app/src/main/java/ch/lin/finance/hub/backend/api/app/service/simulation/core/model/SimulationContext.java)所在的`model`package下新建一個無狀態的utility class，例如`RetirementMonthResolver.java`（純靜態方法，不需要注入，因為輸入只有`birthDate`、`retirementMonthMode`這兩個值,不需要查資料庫或呼叫其他服務）：

```java
public final class RetirementMonthResolver {

    private RetirementMonthResolver() {}

    /**
     * Returns the calendar month (1-12) retirement takes effect in during the
     * given retirement year, or null if birthDate is unavailable (caller should
     * fall back to treating the whole year as retired, matching current behavior).
     */
    public static Integer resolveRetirementMonth(LocalDate birthDate, RetirementMonthMode mode) {
        if (birthDate == null) {
            return null;
        }
        if (mode == RetirementMonthMode.BIRTH_MONTH) {
            return birthDate.getMonthValue();
        }
        return 12; // DECEMBER mode
    }
}
```

**這個方法只回答「退休月是幾月」，不回答「今年是不是退休年」**——「今年是不是退休年」仍然是既有的`age == targetRetirementAge`判斷（在`YearlySimulationPipeline`裡），這份文件不改變這一層。這個方法要解決的是：一旦確定「今年是退休年」，退休月落在1-12的哪一個月。

**如果`birthDate`是null，回傳null**：呼叫方（191-03、191-04）需要處理這個狀況，退回現行「整年視為退休」的行為（即退休月視為1月，或等同於現行`isRetired()`整年判斷），不能讓null導致NullPointerException。這個退回規則由191-03、191-04各自的呼叫點負責判斷，這份文件只定義這個方法本身的行為。

## 討論收斂與實作清單（依據與使用者/PM搭配 question-191 & 191-01 討論結果與系統現行規範更新）

### 1. 核心規則收斂確認
- **DECEMBER 模式行為**：無視生日，固定回傳 `12`（即使 `birthDate == null` 也固定回傳 `12`，不退回 null）。
- **BIRTH_MONTH 模式行為**：依 `birthDate.getMonthValue()` 回傳；僅當 `mode == BIRTH_MONTH` 且 `birthDate == null` 時回傳 `null`（呼叫端退回現行整年退休或 fallback）。
- **回傳值語意**：回傳的月份代表**「最後在職月（Last Working Month）」**（做滿該月最後一天退職）。
  - 例：`DECEMBER` 模式回傳 12，代表該退休年 1～12 月領滿薪水，退休年無年金，次年（66歲）起領年金。
  - 例：`BIRTH_MONTH` 且 1 月生日回傳 1，代表該退休年 1 月領薪水，2～12 月領 11 個月年金，滿 65 歲當月做完即停，不工作到明年。
