# Fixed-39：monthlyPayment 欄位免責聲明形同沒說，未點出「元金均等只填本金」與「獎金情境不適用」兩個關鍵限制

## 現況說明 (Current State)

前端 [page.tsx](../../../../hub-ui/hub-ui/src/app/finance/accounts/mortgages/page.tsx) 目前欄位下方的免責聲明（385-387 行）：

```tsx
<p className="text-xs text-muted-foreground italic">
  * System estimate. Please refer to actual bank details.
</p>
```

不論還款方式（元利均等 / 元金均等）、不論是否設定獎金（`hasBonus`），一律顯示同一句固定文字，且只出現在欄位下方一次，不隨表單狀態變化。

## 問題原因 (Cause)

這句話的意思等同於「這只是估算，不準的話請自己找銀行」——對「估算跟實際會有小數點誤差」這種正常情況或許堪用，但完全沒有點出兩個會讓使用者引用錯誤資料源、或誤信離譜錯誤結果的關鍵陷阱：

1. **對應 [Fixed-37.md](Fixed-37.md)**：沒有講清楚元金均等這個欄位要填的是「本金」，不是銀行給的「當月應繳總額」。這句免責聲明反而在鼓勵使用者去抄一個語意上錯誤的數字進來，因為它沒有指名「該抄哪個數字」。
2. **對應 [Fixed-38.md](Fixed-38.md)**：沒有在設定獎金時給予任何額外或不同的警示。使用者設定獎金後看到的免責聲明跟平常一模一樣，無法辨識「這次的試算結果完全沒有考慮我剛才的設定」。

一句放諸四海皆準、不隨情境變化的免責聲明，實質上等於沒有提供任何可執行的資訊——不管講不講，使用者拿到的資訊量是一樣的。

## 建議修正方向 (Suggested Fix)

把免責聲明從「一句固定文字」改成「隨表單狀態變化、可執行」的提示，兩種情境可同時成立、疊加顯示，不要互相取代：

1. **`repaymentMethod === "EQUAL_PRINCIPAL"` 時**：把提示改成明確指名要填的東西，例如：
   > 「元金均等：請填寫本金部分金額（不含利息），可參考銀行還款計畫表中的『本金』欄位，勿直接填寫『當月應繳總額』。」
2. **`hasBonus` 為真且獎金金額非零時**：額外顯示一句獎金專屬警示，例如：
   > 「⚠️ 已設定獎金還款：此試算結果未考慮獎金設定，可能嚴重偏離實際金額，建議直接參考銀行還款計畫表。」

## 最小範例程式碼 (Sample Code)

```tsx
{formData.repaymentMethod === "EQUAL_PRINCIPAL" && (
  <p className="text-xs text-amber-600">
    * 元金均等：請填寫本金部分金額（不含利息），可參考銀行還款計畫表中的「本金」欄位，勿直接填寫當月應繳總額。
  </p>
)}
{hasBonus && formData.bonusPayments?.some((bp) => (bp.amount ?? 0) > 0) && (
  <p className="text-xs text-red-600 font-medium">
    * ⚠️ 已設定獎金還款：此試算結果未考慮獎金設定，可能嚴重偏離實際金額，建議直接參考銀行還款計畫表。
  </p>
)}
```

## 修正報告 (Resolution Report)

已依照「建議修正方向」完成修復：

1. **前端 (UI)**:
   - 修改了 `page.tsx` 中 `monthlyPayment` 輸入欄位下方的免責聲明區塊。
   - 捨棄了原本單一且無區別性的固定提示，改為基於表單狀態的動態渲染：
     - **元金均等防護**：當選擇 `EQUAL_PRINCIPAL` 時，會出現橘色字體的警告 (`text-amber-600`)，明確引導使用者「請填寫純本金，不要填寫總應繳金額」，解決了 Fixed-37 遺留的 UX 盲區。
     - **獎金還款防護**：當勾選並設定了獎金還款時，會出現紅色粗體的警告 (`text-red-600 font-medium`)，明確告知「目前試算並不包含獎金設定，結果會嚴重偏離，請直接使用銀行提供的數字」，與 Fixed-38 新增的按鈕防呆機制相呼應。
   - 若以上兩個特殊條件皆未觸發，則會優雅降級 (graceful degradation) 顯示原本的預設提示。
   - 提示文字統一採用英文撰寫，以保持 codebase 的一致性。

此修正有效提升了表單的資訊透明度，在使用者最容易犯錯的兩個情境下，提供了即時且具體的引導。
